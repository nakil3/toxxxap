Privacy Policy

Stream Clip Publisher · Last updated: August 2026

Stream Clip Publisher ("the application") is a self-hosted tool operated by an individual developer. This policy explains what data the application handles, where it is stored, and how it is used. The application has no server component, no user accounts and no analytics: it runs entirely on the operator's own computer.

1. Who operates this application

The application is operated by Mark, an independent developer. Contact: YOUR_EMAIL@example.com.

2. What data is collected

The application only handles data belonging to the person who runs it and connects their own social accounts.

Data Why it is needed
TikTok access token and refresh token To authenticate API requests when uploading a video to the connected account.
TikTok account nickname, username and avatar URL Displayed in the publishing panel so the operator can see which account a post will go to before confirming it.
TikTok account posting settings (available privacy levels, whether comment, duet or stitch are disabled, maximum video duration) Used to build the publishing form so that it reflects the creator's own TikTok settings and does not offer options the account does not allow.
Video files produced by the application The clips themselves, created locally from a livestream recording and uploaded to the connected account when the operator confirms publication.
Publication log (timestamp, target account, result of the upload) Shown in the dashboard so the operator can see what was published and diagnose failures.

The application does not collect names, email addresses, phone numbers, location, contacts, browsing history or any other personal information. It does not use cookies, trackers or third-party analytics.

3. Where data is stored

All data listed above is stored locally, in files on the operator's own computer, in the application's working directory. Access tokens are kept in local token files, one per connected account. Video files are kept in a local folder and are deleted automatically after they have been published.

There is no remote database, no cloud storage and no backend service operated by this application.

4. How data is shared

Data is never sold, rented or shared with third parties. Data leaves the operator's computer in exactly two situations:

  • A video file, its caption and its publishing settings are sent to TikTok when the operator confirms a publication.
  • A video file and its metadata are sent to YouTube when the operator publishes to a connected YouTube account.

In both cases the data goes only to the platform the content is being published to, and is handled from that point on according to that platform's own privacy policy.

5. How long data is kept

Access tokens are kept until the operator disconnects the account or the token is revoked. Video files are deleted after publication. Publication logs are kept locally and can be cleared at any time by deleting the corresponding files.

6. Revoking access

Authorization can be withdrawn at any time from the TikTok app itself, in the security settings section that manages permissions granted to connected applications. Removing the authorization there immediately invalidates the tokens held by the application.

Locally, deleting the application's token files has the same effect: the application loses access and must be re-authorized before it can publish again.

7. Children

The application is not directed at children and is not intended for use by anyone under the minimum age required by the platforms it connects to.
